## 实际完成的检查

| 检查 | 方法与范围 |
| --- | --- |
| 版本一致性 | 读取固定提交源码；远端最新提交查询与该基线一致；预览构建核对上游 src 未偏离此提交 |
| 行为与源码 | 阅读 Engine、Intake、Tickets、Policy、Executor、Store、Effects、Outbox 及配套文档，核对接入、授权、派工、反馈、结束与恢复 |
| 文档结构 | `python3 tools/check.py --source /path/to/upstream` 检查本地链接、引用定义、固定源码文件及行号、图像与截图报告 |
| 机制图 | Mermaid CLI 12 解析五张源图，生成 SVG 和 PNG；检查中文、布局、箭头语义与源码一致性 |
| 功能图 | 实际上游 App、CSS、中文文案与静态 API 数据构建，浏览器打开四个页面并截图 |
| 演示边界 | 四个页面无浏览器脚本异常；没有外部请求；每页验证非 GET 写入返回 405；图片保留演示标识 |
| 独立复核 | 一位独立审阅者核对机制、源码、图像和交付范围，未发现阻塞问题；按其建议补齐 dropped 的生命周期路径 |
| 文本格式 | `git diff --check` 检查提交中的空白错误 |

## 仍需真实环境验证的部分

本轮没有运行上游 `pnpm check`，没有配置模型提供者、Agent GitHub 账号或飞书 bot，也没有创建真实 PR、发送消息或验证持续值守效果。

若更新上游基线或截图数据，应重新检查源码引用、机制图和全部四个页面，并同步本记录。
